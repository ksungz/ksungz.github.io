## 도입 배경

UI 개발 리뷰에서는 BEM 네이밍, SCSS 구조와 접근성 속성처럼 반복해서 확인하는 항목이 많았습니다. 회사에서 제공한 AI PR Review Agent가 이런 항목을 먼저 확인할 수 있도록 저장소 적용 과정에 참여했습니다.

## 참여한 범위

Agent 자체를 개발한 것은 아닙니다. UI 파일을 대상으로 하는 필터와 접근성·BEM·SCSS 검토 기준을 정리하고 실행 결과를 확인했습니다.

- SCSS와 HTML 마크업 파일 중심의 필터 기준 정리
- 접근성, BEM 네이밍과 SCSS 작성 규칙을 검토 항목에 반영
- 자동 실행과 수동 실행 결과 확인
- 과한 코멘트와 예외 사례를 확인하고 검토 기준 조정

## 리뷰 대상 항목

| 카테고리 | 점검 항목 예시 |
|---------|--------------|
| 코드 품질 | 불필요한 코드, 중복 선택자, 미사용 변수 |
| 접근성 | ARIA 속성, 시맨틱 태그, alt 텍스트, 키보드 네비게이션 |
| 컨벤션 | BEM 네이밍, SCSS 네스팅 깊이, 클래스 접두사 |
| 성능 | 불필요한 !important, 과도한 셀렉터 특이성 |

## 적용 후 확인한 내용

반복적으로 확인하던 마크업·SCSS·접근성 항목을 AI가 먼저 확인할 수 있는지 적용 과정에서 살펴봤습니다. 설계 의도와 영향 범위, 예외 케이스는 기존 코드 리뷰에서 계속 확인했습니다.

정량적인 시간 절감이나 탐지율은 측정하지 않았습니다.
