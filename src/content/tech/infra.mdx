## 담당 범위

서비스 UI를 구현하는 것과 함께 팀에서 사용하는 빌드와 배포 환경을 유지보수했습니다. Node.js와 Docker 실행 환경을 업데이트하고, 저장소 이관에 맞춰 배포 파이프라인을 구성했으며, 서버 교체 이후 산출물이 정상적으로 반영되는지 확인했습니다.

## 수행한 작업

- 분리돼 있던 정적 리소스 빌드 환경 통합
- Node.js 버전과 Docker 실행 환경 업데이트
- 코드 저장소 이관에 따른 배포 파이프라인 구성과 검증
- 서버 교체 이후 산출물 배포 상태 확인
- 여러 UI 프로젝트의 실행 환경과 배포 설정 일괄 업데이트
- 서버 재시작 이후 필요한 프로세스의 자동 실행 설정

## 운영 문제를 확인한 방식

운영 문제가 발생했을 때 화면 증상만 수정하지 않고 직접 서버 접근 권한을 받아 실행 상태와 배포 결과를 확인했습니다. 개발 환경에서는 재현되지 않는 문제도 있어 실제 배포 상태와 검증 환경을 함께 비교했습니다.

구체적인 서버 구성이나 사내 저장소 정보는 공개 범위에서 제외했습니다. 확인한 사실 이상으로 원인이나 개선 결과를 추정하지 않습니다.

## 이 경험에서 배운 점

프론트엔드 변경도 빌드와 배포 과정이 끝난 뒤 실제 서비스에 반영돼야 완료됩니다. 이후에는 구현 결과뿐 아니라 빌드 성공 여부, 배포된 산출물과 운영 환경의 상태까지 함께 확인하는 기준으로 작업했습니다.
