## 배경

모바일 상품상세의 React 컴포넌트와 운영 SCSS는 서로 다른 저장소에 있었습니다. AI 도구를 활용한 개발 흐름을 개선하려고 컴포넌트와 스타일을 같은 저장소에서 참고할 수 있도록 옮기기로 했습니다.

옮기는 과정에서는 기존 SCSS를 어떤 React 컴포넌트에 연결할지 정해야 했습니다. React 컴포넌트는 기존 SCSS의 화면 블록보다 작은 단위로 나뉘어 있었기 때문입니다.

## 직접 맡은 범위

- 기존 운영 SCSS를 React 저장소로 이관
- 컴포넌트와 SCSS를 연결할 화면 블록 단위 결정
- 신규 UI 블록 약 18개를 중심으로 스타일 적용
- Storybook에서 주요 상태와 화면 결과 확인
- 상품상세 첫 화면(ATF) 개선에 반영

기존 운영 블록 SCSS는 공통 SCSS를 제외하고 약 108개였습니다. 이 스타일을 옮긴 뒤 신규 UI 블록 약 18개를 중심으로 React 컴포넌트에 연결했습니다.

## 구조를 결정한 기준

기존 SCSS 파일과 React 컴포넌트를 하나씩 짝지어 옮기는 방식은 두 구조의 차이에 맞지 않았습니다. 관련 컴포넌트를 화면 블록으로 묶고 그 단위에 기존 SCSS를 적용하기로 했습니다.

신규 UI 블록은 가능한 범위에서 블록과 스타일을 일대일로 연결했습니다. 모든 파일의 형태를 통일하기보다는 실제 화면의 블록과 컴포넌트 관계에 맞춰 옮겼습니다.

## 스타일 적용과 확인

기존 SCSS를 가져온 뒤 React 컴포넌트에 맞게 선택자와 스타일 적용 위치를 조정했습니다. 연결한 화면과 주요 상태는 Storybook에서 확인했습니다.

## 결과와 확인

- 내재화 대상이었던 운영 블록 SCSS를 React 저장소로 모두 옮겼습니다.
- 개발자와 AI 보조 도구가 컴포넌트 코드와 관련 스타일을 같은 저장소에서 참고할 수 있게 됐습니다.
- 해당 스타일 작업은 실제 상품상세 첫 화면(ATF) 개선에 반영됐습니다.

스타일 이관을 완료하고 운영 화면에 반영한 것까지 확인했습니다. 개발 속도나 오류가 얼마나 줄었는지는 별도로 측정하지 않았습니다.
